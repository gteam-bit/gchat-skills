# Крупная схема builder: загрузка JSON-файлом

Используй этот способ, когда полная схема не помещается в аргументы `automation_schema_update`. Он не привязан к конкретному агенту или CLI: нужен доступ к MCP GChat и возможность отправить multipart HTTP POST с **тем же MCP Bearer** из среды, где находится JSON-файл. Подойдёт файл на диске или сформированный клиентом multipart-поток с именем файла `.json`. Если клиент не может отправить HTTP-запрос с тем же токеном, этот способ ему недоступен.

Файл размером до 10 МиБ должен содержать **только объект схемы** с `nodes` и `edges`, без экспортной обёртки `format`, `funnel`, `references`. Байты файла не передавай в аргументах MCP.

1. Найди пространство и автоматизацию через MCP и получи `schema_version` инструментом `automation_get` (он не возвращает схему). Если меняешь существующую схему, работай с её полным актуальным исходником: загрузка файла заменяет схему целиком.
2. Собери JSON-файл в доступной клиенту среде и проверь синтаксис. Не выводи весь файл в чат или аргументы инструмента.
3. Отправь multipart POST на `/mcp/automation-schema-uploads` того же сервера, где расположен MCP endpoint. Передай поля `space_id`, `automation_id` и `file` с именем `.json`, а в заголовке — `Authorization: Bearer <MCP-токен>`. Например, если у клиента есть shell и `curl`:

   ```sh
   curl --fail-with-body --silent --show-error \
     --header "Authorization: Bearer ${GCHAT_MCP_TOKEN}" \
     --form "space_id=${SPACE_ID}" \
     --form "automation_id=${AUTOMATION_ID}" \
     --form "file=@${SCHEMA_FILE};type=application/json" \
     "${GCHAT_BASE_URL}/mcp/automation-schema-uploads"
   ```

   Это пример HTTP-клиента, а не обязательный способ загрузки. Ответ содержит `upload_id`, `expires_at`, `size_bytes`, но не путь S3. Токен не записывай в файл проекта и не выводи в чат или логи.
4. Вызови `automation_schema_update_from_upload` с `space_id`, `automation_id`, `upload_id` и полученной ревизией в `expected_schema_version`. При конфликте ревизии файл остаётся доступным до `expires_at`; проверь актуальный полный исходник схемы перед повтором, чтобы не затереть чужие изменения. После успешного сохранения тот же `upload_id` повторно использовать нельзя.
5. Проверь новую `schema_version` через `automation_get`. Если полный ответ помещается в лимит клиента, перечитай сохранённую схему через `automation_schema_get` и сравни с исходным JSON. Иначе подтверди успешный ответ сохранения и новую ревизию, не утверждая, что вся схема перечитана. Включай автоматизацию лишь если пользователь просил рабочий сценарий.

Этот путь решает передачу готового файла. Если схема ещё не создана, формируй JSON в доступной клиенту среде по частям: один огромный вывод модели всё ещё может превысить лимит клиента. Временный файл удаляется сервером после использования или по истечении 24 часов.
