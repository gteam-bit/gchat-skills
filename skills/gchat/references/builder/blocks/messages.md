# Builder-блоки: сообщения

Общие правила схемы и портов — в [builder.md](../../builder.md). Выражения в текстовых полях — в [Expression Language](../expression-language.md).

У каждого блока обязательны `id` и `type`.

## `send_message`

Отправляет текст клиенту. Поля: `text`, `pinMessage` (boolean), `buttons[]`.

Кнопка:

```json
{
  "id": "button-continue",
  "key": "continue",
  "label": "Продолжить",
  "color": "green",
  "action": { "type": "transition" }
}
```

Цвет: `system`, `red`, `green` или `blue`. `key` кнопки уникален в рамках шага. `action.type` — `transition` или `url`; для `url` передай непустой `url`. Только `transition` создаёт выходной порт, который соединяется ребром. URL-кнопка не создаёт ветку builder.

## `send_system_message`

Поля: `text`. Используй этот тип только для системного текстового сообщения, как он предусмотрен в нужном сценарии; не подменяй им клиентский ответ `send_message`.

## `send_media_text`

Поля: `text`, `mediaFileIds[]`, `pinMessage`, `buttons[]`. Можно отправить текст, медиа или оба вида содержимого. Блок не исполняется, если после подстановки нет ни текста, ни медиа. ID файлов должны быть существующими UUID; инструмента поиска медиа в GChat MCP нет. Кнопки используют тот же контракт и правила портов, что у `send_message`.

## `send_voice` и `send_video_note`

Поля: `mediaFileId`, `pinMessage`. Успешное исполнение требует непустой ID существующего файла подходящего типа. Тип схемы допускает `mediaFileId: null` для незаполненной заготовки, но executor завершится ошибкой, если такой блок запустить без ID. Не включай его как готовое действие с `null`.

Для медиа-блоков не придумывай ID. Используй ID, подтверждённый в существующей схеме или предоставленный пользователем. `pinMessage` — boolean.
