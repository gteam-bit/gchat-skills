# Рабочие сценарии GChat MCP

## Найти клиента по имени и его чаты

1. Вызови `chats_list` с `search` по имени клиента и подходящим `limit`; проходи следующие страницы по `cursor`. Результаты ограничены видимостью чатов текущего пользователя и правами токена.
2. Сопоставь точное имя и дополнительные признаки: телефон, интеграцию, теги, последние сообщения. Одинаковые имена не считай одним клиентом.
3. Возьми `client.id` из подходящей записи и вызови `client_get`, чтобы проверить карточку, комментарий, теги и поля.
4. Для переписки передай `chat.id` в `chat_get` и `chat_messages_list`. У клиента может быть несколько чатов — проверь интеграцию и нужный канал.

Поиск `chats_list` охватывает имя, телефон, ID клиента, внешний ID клиента, ID чата и внешний ID чата. Он не предназначен для полнотекстового поиска по истории сообщений; для этого нужен `chat_messages_list` с уже найденным `chat`.

## Найти запуск автоматизации клиента, если известно только имя

1. Найди UUID клиента через `chats_list(search=<имя>)` и разреши неоднозначность через `client_get`.
2. Найди пространства через `automation_spaces_list`, проходя страницы. В каждом вероятном пространстве вызови `automations_list`; сравни имена и уточни кандидата через `automation_get`.
3. Для каждой подходящей пары `space_id`/`automation_id` вызови `automation_logs_conversations_list` с `search=<client UUID>`. По необходимости добавь один `status` из `running`, `waiting`, `completed`, `failed`, `cancelled`; проходи страницы.
4. Открой найденную сессию через `automation_logs_conversation_get`. Для длинного трейса читай `automation_logs_conversation_outline` страницами, затем загружай интересующие события через `automation_logs_trace_event_get`. Сопоставляй сообщения через `automation_logs_conversation_messages`.
5. Если известен `run_id` или нужен весь запуск, используй `automation_logs_runs_list` или `automation_logs_run_trace`.

Список conversations фильтрует по ID клиента, ID чата, ID сессии, ID стартового сообщения и тексту стартового сообщения. Отчёты о conversion-rate отдельным инструментом не предоставляются: из логов можно подтвердить статус и последовательность событий. Не называй `completed` конверсией без заранее согласованного бизнес-признака.

## Создать автоматизацию по имени пространства и имени тега

1. Найди пространство через `automation_spaces_list(search=<имя>)`. Сверь результат через `automation_space_get(space_id)`; если точного совпадения несколько, не выбирай по позиции в списке.
2. Найди тег через `tags_list(search=<имя>)`; если совпадений несколько, прочитай подходящие `tag_get(id)`. Запомни UUID, не используй отображаемое имя вместо ID.
3. Выбери событие по формулировке запроса:
   - тег добавили → `client.tag.added`;
   - тег удалили → `client.tag.removed`;
   - любое изменение тега → `client.tag.changed`.
   Если пользователь описал только тег, но не событие, не подменяй его догадкой: уточни добавление/удаление/любое изменение.
4. Создай метаданные:

   ```json
   {
     "space_id": "<UUID пространства>",
     "name": "<имя автоматизации>",
     "trigger_type": "client.tag.added",
     "trigger_settings": { "tag_ids": ["<UUID тега>"] }
   }
   ```

   Используй `automation_create`. Для `client.tag.removed` или `client.tag.changed` замени только `trigger_type` на согласованный тип.
5. Автоматизация создаётся выключенной. Если пользователь указал только имя и триггер, не выдумывай действия: сохрани её как выключенную заготовку и сообщи, что нужно определить, что должно произойти после триггера. Если действие задано, построй схему по [общему контракту builder](builder.md) и только нужным профильным справочникам из `builder/`; прочитай ревизию через `automation_schema_get`, полностью сохрани схему через `automation_schema_update`, перечитай её для проверки и вызови `automation_enable`, если запрос подразумевает рабочий/активный сценарий.

`trigger_settings.tag_ids` должен содержать ID существующего тега той же организации. Не передавай `organization_id`: границы организации задаёт токен.

## Изменить автоматизацию

1. Найди её через пространство и `automations_list`; проверь UUID с `automation_get`.
2. Для изменения имени или триггера передай полный набор новых метаданных в `automation_update`. Этот инструмент заменяет метаданные и сохраняет текущее состояние `enabled`.
3. Для изменения поведения прочитай актуальную схему и ревизию через `automation_schema_get`. Внеси изменения в полную схему, увеличивать `expected_schema_version` вручную не нужно: передай полученное значение. Если пришёл конфликт, снова прочитай схему, собери обновление поверх неё и повтори.
4. Включение и выключение делай отдельными `automation_enable` и `automation_disable`. Включение проверяет схему выборочно и не доказывает, что все значения и ветки исполнятся; перед активацией сверь схему с профильными builder-справочниками.

## Найти нужные ID ресурсов

Доступные справочники: пространства — `automation_spaces_list`; теги — `tags_list`; пользовательские поля — `custom_fields_list`; автоматизации — `automations_list`; клиенты — через результат `chats_list`. Сотрудников и группы для чата можно искать инструментами `chat_assignees_list` и `chat_transfer_groups_list`, если известен `chat`.

В текущем реестре нет MCP-поиска медиафайлов, моделей ИИ и баз знаний. Для блоков, которым они нужны, используй ID, уже присутствующий в прочитанной схеме или предоставленный пользователем; не подбирай ID перебором. Если ID нельзя подтвердить доступными инструментами, оставь блок незаполненным и попроси нужный идентификатор либо выбери другой блок.
