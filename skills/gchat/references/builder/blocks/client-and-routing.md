# Builder-блоки: клиент, маршрутизация и значения

Общие правила схемы и портов — в [builder.md](../../builder.md). Для выражений см. [Expression Language](../expression-language.md), для объявления переменных — [переменные](../variables.md).

У каждого блока обязательны `id` и `type`.

## Теги клиента

`client_add_tags` и `client_remove_tags` используют `tagIds[]` — список UUID тегов организации. Сначала найди нужный тег через `tags_list` и сверь имя. Не подставляй отображаемое имя вместо UUID.

## Пользовательское поле клиента

`client_update_custom_field` имеет поля `customFieldId` и `value`. Используй ID поля из `custom_fields_list`; значение передавай строкой или выражением в поддерживаемом шаблонном поле. Хотя схема редактора разрешает `customFieldId: null`, runtime в этом случае ничего не меняет. Для рабочего действия укажи реальный ID.

## Передача чата

`chat_transfer` имеет `staffProfileId` и `groupId`. Укажи ровно одного адресата: сотрудника или группу. Если оба значения пусты/null, блок становится no-op; если заданы оба, runtime завершит его ошибкой.

Найди адресата по известному чату через `chat_assignees_list` или `chat_transfer_groups_list`; используй выданный ID, не имя.

## Переменная воронки

`set_variable` имеет поля `targetVariablePath` и `value`. Цель должна быть заранее объявленной переменной `funnel.*` подходящего типа. Новые схемы сохраняют полный путь, например `funnel.incoming_text`; старый bare `key` — только compatibility-поле, не создавай его.

`value` — текстовое значение/шаблон; expression обрамляй фигурными скобками, например `{sys.message.text}` или `{lowercase(sys.message.text)}`. Запись выполняет `BuilderVariables`; не рассчитывай, что системная или env-переменная станет изменяемой от указания её в качестве цели.
