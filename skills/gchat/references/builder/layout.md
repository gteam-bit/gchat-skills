# Размещение узлов на схеме

Размещай узлы так, чтобы координаты поддерживали чтение графа: сначала виден основной ход слева направо, затем — отдельные ветви, циклы и участки ожидания. Порядок исполнения задают `edges` и handles; сами координаты его не меняют.

## Поведение canvas

- Сетка canvas — `20 × 20`. UI привязывает новые или перемещаемые узлы к этой сетке.
- Ширина `step`-узла — `320 px` (16 ячеек), ширина `start` — `160 px` (8 ячеек). Высота `step` не фиксирована: UI измеряет реальный DOM через `ResizeObserver`; fallback `160 px` применяется до первого измерения и не подходит для расчёта готовой схемы.
- При перемещении `start` и `step` интерфейс проверяет их фактические размеры и не даёт поставить их в позицию с пересечением, оставляя зазор в одну ячейку. Это ограничение интерактивного canvas, а не гарантия backend для импортированной JSON-схемы.
- Автоматически добавленный первый `step` помещается справа от `start`; следующие шаги — справа от самого правого шага. При столкновении UI ищет свободное место сдвигом вправо на одну ячейку, сохраняя строку.
- Узел `note` — визуальная нода без рёбер. Он располагается за `start` и `step`, не участвует в проверке их столкновений и может пересекаться с ними.
- Размер новой note по умолчанию — `360 × 240`; в редакторе заметку можно растянуть, чтобы оформить большую группу узлов.
- Note имеет минимум `240 × 160 px`. В компоненте canvas заголовок отступает от границ только на `16 px` (`px-4 py-4`). Чтобы заголовок и узлы не выглядели прижатыми к рамке, оставляй от верхнего края note до верхнего ряда узлов не менее `80 px`, по бокам и снизу — не менее `40 px`.

## Оценка высоты step-узлов

В исходниках frontend `AutomationBuilderStepNode` формирует высоту из заголовка, сводки, списка блоков, списка триггеров и нижнего hint-элемента. Высота меняется при добавлении блоков, выходов блока и триггеров; поэтому считай её по содержимому, а не по одному постоянному числу. Следующие значения — консервативная оценка для планирования JSON-раскладки, а не контракт CSS:

| Элемент | Плановая высота |
|---|---:|
| Каркас узла: header, внутренние отступы, summary, footer и section gaps | `160 px` |
| Обычная карточка блока без выходов | `80 px` |
| Карточка блока с `n` вложенными портами (кнопками/маршрутами) | `80 + 24 + 40n + 8(n−1) px` |
| Строка триггера `goto` без описания | `40 px` |
| Строка `condition`, `condition_else`, ожидания или иного триггера с описанием | `52 px` |
| Внутренний отступ списка блоков или триггеров | `20 px` на список |
| Зазор между карточками/строками в списке | `8 px` |
| Summary и промежуток между секциями | `24 px` и `12 px` соответственно |

Перед расчётом сначала учти элементы, которые frontend добавляет при отображении, а не только сохранённый JSON:

- Если в `data.triggers[]` шага есть хотя бы один `condition`, UI нормализует список и добавляет ровно один `condition_else` (либо использует уже сохранённый). Это ещё одна видимая строка триггера; несколько `condition` создают общую последовательность `IF`/`ELSE IF` и один общий `ELSE`, а не отдельный fallback на каждое условие.
- `ai_router` рендерит вложенный порт для каждого маршрута плюс один `fallback`-порт.
- `send_message` и `send_media_text` рендерят вложенный порт только для каждой кнопки с `action.type: "transition"`. Кнопки `url` высоту порт-листа не добавляют.
- По текущей карте `getAutomationBuilderBlockPorts()` остальные типы блоков не добавляют вложенные порты. При появлении нового типа блока перепроверь эту карту в `frontend/src/features/automatization-builder/model/block/mapper.ts`.

Затем сложи каркас, summary, список блоков и нормализованный список триггеров, включая отступы и промежутки. Число выходов `ai_router` и кнопок `transition` прибавляй к высоте соответствующей карточки блока, а не к списку триггеров шага. `condition_else` учитывай в высоте триггерного списка, даже если его нет в прочитанной схеме до нормализации. Длинный preview обычно ограничен двумя строками, но локализованные названия, ошибки и описания триггеров могут увеличить карточку — округляй оценки вверх до ближайших `20 px`.

После оценки добавляй **не менее `40 px` запаса между границами соседних `start`/`step`-узлов** по горизонтали и вертикали. UI-интерактивно оставляет 20 px, но для вручную сохранённой схемы нужен дополнительный запас. При ветвлении размещай узлы в отдельных вертикальных дорожках; следующую строку начинай только после `max(y + estimatedHeight)` предыдущей дорожки плюс 40 px. `note` не участвует в проверке пересечений.

Note размечай отдельными рамками вокруг групп: оставляй минимум `80 px` сверху для заголовка и воздуха, `40 px` по бокам и снизу. Между прямоугольниками соседних note оставляй минимум `40 px` видимого canvas-фона — края не должны касаться. Эти зазоры создавай координатами и размерами note, а не наложением фонов. Вручную проверь, что заметка не закрывает несвязанную группу.

Автоматическое добавление `condition_else` выполняет `normalizeConditionStepTriggers()` при подготовке документа; список block ports задаётся исчерпывающей картой `AUTOMATION_BUILDER_BLOCK_PORT_RESOLVERS`. Для пересчёта высот используй нормализованный trigger-list и ports, вычисленные из каждого блока. Эти значения проверены по `frontend/src/features/automatization-builder/modules/canvas/widgets/AutomationBuilderCanvas/components/AutomationBuilderCanvasStepNode.tsx`, `AutomationBuilderCanvasStepNodeBlockList.tsx`, `AutomationBuilderCanvasStepNodeBlockPortList.tsx`, `AutomationBuilderCanvasStepNodeTriggerList.tsx`, `frontend/src/features/automatization-builder/model/condition/mapper.ts`, `model/block/mapper.ts`, `model/document/transform.ts` и `frontend/src/features/automatization-builder/lib/canvas-geometry.ts`. Если canvas-компоненты, нормализация триггеров или карта выходов блока изменились, перечитай эти источники перед расчётом новой схемы.

Это поведение интерфейса, а не полный авто-layout. При создании JSON вручную явно задавай позиции для всего графа; автоматическое добавление шагов не выбирает строки ветвей по их смыслу.

Размер note и её внутренний отступ сверены с `frontend/src/features/automatization-builder/modules/canvas/widgets/AutomationBuilderCanvas/components/AutomationBuilderCanvasNoteNode.tsx`: компонент использует `px-4 py-4` (16 px), а resizer ограничивает минимум до `240 × 160 px`.

## Что видно в референс-схемах

- Основные координаты в пяти из шести схем кратны 20. В меню-схеме есть шесть узлов с координатами, не кратными сетке. Для новых схем используй шаг 20; старые координаты считай особенностью экспорта/редактирования, а не шаблоном.
- Компактные сценарии идут слева направо и расходятся на отдельные ветви после условия. В длинных сценариях сохраняй это направление внутри смыслового участка, а сами участки выстраивай отдельными полосами.
- Ветви выходят как из триггеров (`step-trigger:<triggerId>`), так и из кнопок (`block-port:<blockType>:<blockId>:<buttonKey>`). Размещай целевые шаги каждого выхода рядом с соответствующей веткой и учитывай оба вида портов.
- Сценарии с меню группируют кнопочные переходы вокруг исходного сообщения; связанные шаги меню, FAQ и уроков образуют отдельные последовательности/подграфы. Не располагай такие цели одним тесным списком, если рёбра начинают пересекаться.
- В ожиданиях с `any_message` и `timeout` альтернативные продолжения обычно разнесены по разным строкам. Сохраняй порядок выходов, подписывай шаги по их назначению и не сливай две ветви в одну визуальную линию до реального места схождения.
- Большие сценарии повторяют вертикальные дорожки для отдельных продуктов, стадий или ответов. Для такого графа сначала выдели смысловые группы, затем размещай их как отдельные полосы; не пытайся растянуть всё в одну цепочку.
- В одном большом референсе четыре крупные note обрамляют группы узлов как фоновые секции. Размеры этих заметок значительно больше значения по умолчанию. Используй note для визуального разделения большого workflow, а не только как маленький комментарий.
- В одном из menu-heavy референсов обнаружены позиции вне сетки, а пара близко расположенных узлов может пересекаться при стандартной оценке высоты. Перед копированием старой раскладки проверь её в canvas.
- В одном большом референсе есть изолированный `step` без входящих и исходящих рёбер. Для новых схем проверяй такие шаги отдельно: оставляй их только если они намеренно отключены, иначе подключи к графу.

## Правила компоновки для новых схем

1. Поставь `start` в начале графа, основной путь веди слева направо.
2. Для каждого выхода условия или кнопки выдели отдельное направление/строку. Сохраняй порядок ветвей из конфигурации; `else` ставь после именованных условий. Положение должно помогать сопоставить ребро с его подписью.
3. Если пути сходятся, веди их к одному целевому узлу только в реальной точке схождения. Для повторяющихся путей делай одинаковые этапы в одинаковых колонках.
4. Цикл или возвратный переход показывай как отдельную обратную связь вокруг группы, чтобы обратное ребро не пересекало основную последовательность без необходимости.
5. Оставляй между рабочими узлами место для их динамической высоты, портов и подписей рёбер. Проверяй пересечения по реальным границам блоков, а не только по координатам их верхнего левого угла.
6. Ставь `note` рядом с группой, которую она обозначает. Для большой группы растяни note в фон-секцию; не закрывай текстом заголовки и порты. Не связывай note с рёбрами и не используй вместо исполняемого `step`.
7. Давай шагам содержательные короткие заголовки. Не оставляй шаблонные `Step N`, если назначение уже известно: названия помогают читать схему и различать повторяющиеся ветви.

## Проверка готовой раскладки

- Координаты новых узлов кратны 20.
- Все `start` и `step` видимы и не перекрываются с зазором не менее `40 px`; оценка учитывает авто-добавленный `condition_else`, все вложенные порты `ai_router` и все кнопки `transition` в `send_message`/`send_media_text`.
- Каждая note имеет не менее `80 px` сверху до верхнего ряда группы и `40 px` по бокам/снизу; между соседними note остаётся не менее `40 px` canvas-фона.
- У каждого `step` есть ожидаемый входящий путь либо явно объяснено, почему узел пока изолирован; недостижимые узлы не считай частью рабочего потока.
- Каждое ребро можно проследить от конкретного порта до целевого шага. Отдельно проверь связи кнопок, условий, `else`, ожиданий и возвратов.
- Крупные группы различимы по расположению, а note поясняют секции вместо того, чтобы прятать рёбра или подписи.
- Координаты соответствуют именно этому графу. Не копируй раскладку целиком из другого workflow.
